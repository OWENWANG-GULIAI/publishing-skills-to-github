# GitHub 安全发布流程

## 1. 解析发布目标

确认本地 Skill 根目录、Git 仓库根目录、远端地址、当前分支、默认分支、GitHub owner、仓库名、可见性和用户要求的最终结果。区分以下任务：

- 更新已有仓库；
- 创建新仓库；
- 只优化仓库介绍页面；
- 创建或同步多包 Skill 合集；
- 修改 owner、名称、可见性或许可证——这些是独立变更。

不能仅根据“发布”二字推断用户同意转移仓库、重命名、公开发布或强制推送。

## 2. 编辑前完整检查

单 Skill 仓库：完整读取 `SKILL.md`、它引用的资料、脚本、测试、资源、元数据、当前 README、许可证、Git 状态、近期历史和远端配置。记录无关的已修改或已暂存内容，并保持不动。

多包合集：完整读取根 README、`catalog.json`、`LICENSES.md`、各包的 `SKILL.md`、包级许可证、来源映射、引用资源、测试、Git 状态、近期历史和远端配置。根目录不应因缺少 `SKILL.md` 被当作失败；要确认每个目录包才是可安装单元。

依据当前文件建立 README 规范中的事实清单。当 owner、可见性、默认分支、Release 或远端内容可能变化时，必须实时读取 GitHub 状态。

## 3. 撰写或修订 README

模板只提供结构起点。根据产品叙事调整顺序，删除没有事实支撑的部分，保留已有的高质量内容。即使用户要求“快速同步”，也必须核验全部 README 核心要求并修正过期内容。

专业质量不等于制造改动。如果当前 README 已符合规范且准确反映 Skill，应记录核验结果并保持原文不变。

## 4. 审计与验证

使用核实后的 owner 和仓库名运行确定性审计。根据仓库实际情况继续执行：

- 官方 Skill 验证器；
- 仓库单元测试或集成测试；
- 安装与调用检查；
- Markdown 链接检查；
- 压缩包完整性检查；
- 基于差异的隐私和凭证检查。

合集审计使用：

```bash
python3 scripts/audit_skill_repository.py \
  --collection-root <target-skill-collection> \
  --repo-owner <github-owner> \
  --repo-name <repository-name> \
  --json
```

它会检查根 README、`catalog.json`、`LICENSES.md`、每个声明包的 `SKILL.md` 与 MIT 声明是否匹配；仍需运行每个有测试或验证器的包的相关检查。

必须阅读检查输出，不能只看退出码。发现失败后修复根因并重新运行。

## 5. 复核准确的发布范围

检查 `git status`、未暂存差异和已暂存差异。只暂存明确的目标路径，确认提交中不含用户原有工作、缓存、凭证、个人信息和本机路径。

使用用户批准的提交身份。如果用户采用 GitHub ID 型 noreply 邮箱，要根据当前账号 ID 和 login 动态生成，不要硬编码可能过期的地址。

## 6. 安全发布

- 已有仓库：必要时先获取远端状态并检查分歧，提交目标文件后普通推送。
- 新仓库：只在 owner 和可见性得到明确授权后创建，不在远端初始化会与本地冲突的历史。
- 没有单独明确授权，绝不强制推送或改写历史。
- 不把所有权转移、账号或仓库重命名、可见性或许可证变更作为附带操作。

如果远端改动与本地工作冲突，应停止并说明冲突，不能覆盖任何一方。

## 7. 回读远端结果

推送后必须读取远端仓库，不能停留在本地 Git 输出。核对：

- 仓库规范 URL 和 owner；
- 可见性和默认分支；
- 远端最新提交与预期本地提交一致；
- README 来自预期分支并正常呈现；
- README 链接和徽章指向真实资源；
- GitHub 展示的许可证与仓库文件一致。

对于合集，还要回读 `catalog.json`、`LICENSES.md` 和至少一个包路径，确认根目录没有错误地作为单一 Skill 或统一许可证发布。

最终报告仓库 URL、提交标识、变更文件、执行过的检查和剩余边界。本地提交成功、命令返回成功或界面提示成功，都不能单独证明发布完成。

## 常见失败

| 失败方式 | 正确处理 |
|---|---|
| “README 已存在，所以跳过” | 按完整规范和当前 Skill 重新评估。 |
| 赶时间就删除 README 工作 | 可以减少装饰，不能减少事实核心、隐私检查和远端证明。 |
| 账号改名后仍保留旧 owner | 搜索全仓库链接，并验证规范远端 URL。 |
| 通用模板夸大能力 | 删除无依据文案，依据事实清单重写。 |
| 把整个脏工作区暂存 | 安全撤出非目标内容，只暂存准确路径。 |
| Push 提示成功但页面仍旧 | 回读远端分支和 README，并比较提交标识。 |
