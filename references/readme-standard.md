# README 专业规范

README 是仓库的公开产品介绍页，不是文件清单。第一次进入仓库的人应该能迅速回答：这是什么？是否适合我？是否可信？如何开始？有什么边界？

## 先建立事实清单

写作前，从当前仓库提取并核验以下事实：

| 项目 | 可接受的证据 |
|---|---|
| 名称与一句话价值 | `SKILL.md`、产品说明、实际可运行行为 |
| 目标用户与场景 | 明确的适用范围和受支持示例 |
| 触发方式、输入和输出 | `SKILL.md`、测试、验证过的命令 |
| 工作流程 | 实际指令与脚本 |
| 安装和使用 | 已运行或能够验证的命令 |
| 兼容性与依赖 | 清单文件、文档、运行环境检查 |
| 版本与状态 | Release、标签或明确的项目版本 |
| 许可证 | 仓库许可证文件与依赖约束 |
| 当前边界 | 已知不支持的行为与授权限制 |

缺少证据时，删除对应表述、标记为尚未验证，或把它明确写成当前限制。不得把规划中的能力描述成现有功能。

## 推荐页面结构

除非 Skill 的特点需要更清晰的变体，README 按以下顺序组织：

1. **首屏 Hero**：居中标题、简短中文价值主张、可选英文副标题。
2. **默认 GULIAI 品牌模式**：所有 Skill 发布默认使用 GULIAI Logo。使用已确认的官方 Logo 原图，不重绘、不变形、不添加滤镜；首屏顺序为 Logo、标题、价值主张、真实徽章，随后用左侧竖线卡片呈现“定位 / 不做什么”。Logo 资产缺失时停止发布并报告阻塞，不得以中性 Hero 替代。
3. **真实徽章**：默认 GULIAI 品牌模式下，版本、语言、许可证三类徽章为必填，且必须有当前文件依据；运行环境或兼容性徽章按事实添加。只有对应目标真实存在且保持更新时，才添加 CI、Release、覆盖率或下载量徽章。
3. **页内导航**：较长页面提供精简锚点。
4. **定位说明**：用“是什么／不是什么”快速划定边界。
5. **为什么需要它**：说明用户问题和差异化价值。
6. **快速开始**：准确的克隆、安装、调用步骤和预期输出。
7. **工作原理**：呈现真实流程；只有多阶段关系确实更容易理解时才使用 Mermaid。
8. **核心能力与适用场景**：使用具体、有限、可核验的表述。
9. **示例**：使用虚构或充分匿名化的数据，保留证据形态但不暴露真实信息。
10. **输入与输出**：说明格式、必要上下文和生成物。
11. **仓库结构与质量保证**：只链接真实存在的文件和目录。
12. **隐私、安全、授权与版本边界**：把公开使用限制写清楚。
13. **参与贡献、许可证和结语**：明确复用权利，并链接实际许可证文件。

## 写作规则

- 先说明用户价值，再解释实现。
- 用准确示例和可执行命令代替形容词。
- 标题便于浏览，段落保持简短。
- 以目标读者的主要语言为主；双语内容应提供额外价值，不要整页机械重复。
- 使用相对链接指向 `SKILL.md` 和参考资料，保证 Fork 后仍然有效；品牌 Logo 也应使用仓库内相对路径或用户明确批准的稳定地址。
- 不添加没有依据或不能帮助理解的徽章、截图、流程图和表格。
- 没有证据时，不得宣称“生产可用”“安全”“官方”“完整”或支持某个平台。
- 公开 README 不得出现机器专属的绝对路径。

## README 验收清单

- 新访客在首屏就能理解用途、目标用户和第一步操作。
- 克隆、安装、调用命令与当前仓库一致。
- 所有链接和锚点都能访问。
- 功能、示例、流程图、文件树、徽章、版本和许可证与当前文件一致。
- 隐私与授权边界清晰可见，而不是藏在实现说明中。
- 不含直接身份信息、凭证、私聊、客户数据和本机路径。
- 页面针对当前 Skill 写作，而不是未完成替换的通用模板。
- 已核验默认 GULIAI Logo、定位卡和三类真实徽章，而不是只保留普通 Markdown 标题。
## 多包合集仓库

当仓库的作用是收录多个可独立安装的 Skill 时，根目录是“发现与分发页”，不是一个伪装成 Skill 的目录。此时仍遵守首屏品牌、真实徽章、定位卡、快速开始和隐私边界，但采用以下结构：

- 根目录不需要 `SKILL.md`；只有根目录确实提供独立编排能力时，才可添加它自己的 `SKILL.md`。
- 使用 `catalog.json` 记录每个包的稳定 id、相对路径、来源仓库和许可状态；README 的目录表应链接到来源或包路径，并声明旧独立仓库的保留策略。
- 使用 `LICENSES.md` 解释包级许可。仅当每个可再授权内容都已核验兼容、且用户明确授权时，才可在根目录新增统一许可证。
- 徽章中的许可证可写为 `per-package`，但不能显示为 MIT、Apache 或其他统一授权，除非根目录确实具备该许可证。
- 快速开始应说明“复制单个包”或其他实际安装范围；不能把整套合集描述成一个可直接安装的单一 Skill。
- README 必须说明同步/维护来源，避免读者误以为旧仓库会自动与合集双向同步。
