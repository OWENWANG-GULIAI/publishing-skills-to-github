# 隐私、身份与许可证规范

## 公开信息检查

公开仓库是长期、可搜索的信息发布。检查已跟踪文件、拟提交差异、示例、测试数据、生成物和压缩包，重点识别：

- Access Token、API Key、Cookie、密码、私钥和连接字符串；
- 未明确批准公开的直接邮箱；GitHub noreply 邮箱可以作为经批准的提交身份；
- 手机号、身份证号、地址、账号 ID 和私人档案信息；
- 来自私聊、客户项目、访谈或内部资料的真实姓名和可识别引文；
- 本机绝对路径、设备名、用户名、内部 URL 和文件系统结构；
- 未获得公开授权的客户名称、Logo、截图、指标和评价；
- 图片、压缩包、Office 文件或导出数据中的隐藏元数据。

示例默认使用虚构数据。匿名化不只是替换姓名，还要删除能组合识别个人的公司、时间、职位、项目等线索。

Git 提交作者身份属于公开元数据，只能使用用户批准的身份。当前用户批准的显示名是 `王跃平 OWENWANG`；GitHub ID 型 noreply 邮箱必须根据当前核实的账号动态生成，不能把旧邮箱当作永久值。

## 许可证决策

公开仓库即使没有开源许可证，也只是允许他人查看，并不会自动授予复用、修改和分发权。README 必须准确说明当前许可状态。

只有同时满足以下条件时，新仓库才可以采用 MIT：

- 用户明确希望公开开源；
- 用户对代码和文档拥有授权；
- 所含资源与依赖不存在冲突条款；
- 没有需要保留的既有仓库许可证。

已有仓库默认保留原许可证，除非用户明确授权变更。不得默默把“无许可证”、专有声明或其他开源许可证替换成 MIT。

添加许可证前，要检查第三方代码、模板、字体、图片、模型、数据集和转载文档。它们可能有独立的署名与再分发要求，不能只看顶层许可证。

## 必须单独授权的变更

- public、private 或 internal 可见性变更；
- 仓库或账号重命名；
- 所有权转移；
- 为已有仓库添加或替换许可证；
- 修改默认分支；
- 强制推送、历史改写、删除标签或 Release；
- 发布此前属于私有的用户或客户数据。

授权信息缺失时，可以完成安全的本地准备，并明确指出被阻塞的外部变更；不能从相邻请求推导更大范围的同意。
